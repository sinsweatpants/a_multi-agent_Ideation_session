توثيق مشروع: نظام تطوير القصص متعدد الوكلاء
مقدمة
هذا المشروع عبارة عن تطبيق ويب متكامل يهدف إلى تطوير الأفكار القصصية باستخدام نظام متعدد الوكلاء (Agents)، حيث يتعاون فريق من الوكلاء المتخصصين في مجالات السرد، بناء الشخصيات، التوتر، وغيرها، لتوليد أفكار قصصية متكاملة وتحليلها ومراجعتها بشكل جماعي وتفاعلي.

الهيكل العام للمشروع
- `agents/`: يحوي ملفات تعريف وكلاء الذكاء الاصطناعي.
- `public/`: واجهة المستخدم (HTML, CSS, JS).
- `orchestrator.js`: المنسق الرئيسي الذي يدير منطق كل مرحلة من مراحل سير العمل.
- `server.js`: خادم Express.js الذي يدير الجلسات (sessions) ويخدم الواجهة ويوفر نقاط API لكل مرحلة.
- `package.json`: إدارة الحزم والاعتمادات.

شرح وكلاء النظام (Agents)
كل وكيل عبارة عن ملف JS يمثل خبيرًا في مجال معين، مثل:
- `storyArchitectAgent`: بناء الهيكل السردي.
- `characterDevelopmentAgent`: بناء شخصيات عميقة.
- `strategicAnalystAgent`: تحليل الأفكار ودمجها.
- `audiencePersonaAgent`: محاكاة رد فعل شريحة معينة من الجمهور.
- ... وغيرهم من الوكلاء المتخصصين.

سير العمل البرمجي المحدث
تمت إعادة هيكلة المشروع ليعمل بنظام تفاعلي قائم على الجلسات والمراحل المتعددة، بدلاً من النظام السابق الذي كان ينفذ كل شيء في خطوة واحدة.

**الواجهة الأمامية (Client-side):**
1.  **بدء الجلسة:** يُدخل المستخدم مفتاح API وموجزًا إبداعيًا.
2.  **التفاعل المرحلي:** تعرض الواجهة نتائج كل مرحلة وتوفر أزرارًا للمستخدم لاتخاذ قرارات (مثل اختيار الأفكار، بدء النقاش، اتخاذ القرار النهائي) والانتقال إلى المرحلة التالية.
3.  **عرض التقرير:** في النهاية، يتم عرض تقرير شامل ومفصل لكل جوانب عملية التطوير.

**الخادم والمنسق (Server-side):**
يدير الخادم (`server.js`) الحالة الكاملة لكل جلسة تطوير، ويستدعي المنسق (`orchestrator.js`) لتنفيذ المنطق الخاص بكل مرحلة عبر نقاط API محددة.

**مراحل سير العمل (Workflow Stages):**

1.  **`POST /api/start-session` (مرحلة التشتيت الإبداعي - Divergence):**
    -   يختار المنسق 5 وكلاء بشكل شبه عشوائي.
    -   يولد كل وكيل "ملخصًا قصصيًا" (Logline) فريدًا باللغة العربية.
    -   تُرسل الأفكار الخمس إلى الواجهة ليختار المستخدم منها.

2.  **`POST /api/select-ideas` (مراحل الدمج، المراجعة، والتنقيح):**
    -   **الهجنة (Hybridization):** يختار المستخدم فكرتين. يقوم `strategicAnalystAgent` بدمجهما في فكرة ثالثة هجينة.
    -   **المراجعات (Reviews):** يقوم جميع الوكلاء بمراجعة الأفكار الثلاث (المختارة والهجينة) وتقديم ملاحظات نقدية.
    -   **التنقيح (Refinement):** تُرسل الملاحظات إلى الوكيل الأصلي لكل فكرة لإنتاج نسخة منقحة ومحسنة.

3.  **`POST /api/debate` (مرحلة النقاش الموضوعي):**
    -   تُعقد ثلاث جولات نقاش منظمة (حول البنية، الشخصيات، والتجربة).
    -   في كل جولة، يقدم وكيلان متخصصان تحليلاً مقارنًا للأفكار الثلاث المنقحة.
    -   يتم اختيار وكيل "محامي الشيطان" (Devil's Advocate) بشكل عشوائي لتحدي الحجج المقدمة وكشف نقاط الضعف.

4.  **`POST /api/audience` (مرحلة صوت الجمهور):**
    -   يقوم `audiencePersonaAgent` بمحاكاة شخصية جمهور محددة (مثل "مراهق محب للخيال العلمي").
    -   يصوت هذا الوكيل للفكرة الأكثر جاذبية من منظوره ويقدم مبرراته.

5.  **`POST /api/decide` (مرحلة القرار والتحليل النهائي):**
    -   **القرار (Decision):** يتخذ المستخدم (المنسق البشري) القرار النهائي ويختار الفكرة الفائزة.
    -   **تحليل الإنقاذ (Salvage Analysis):** يتم تحليل الأفكار الخاسرة لاستخلاص عناصر قيمة يمكن دمجها في الفكرة الفائزة.
    -   **اختبار الإجهاد (Stress Test):** يتم إجراء اختبار إجهاد نهائي للفكرة الفائزة لتحديد أي ثغرات منطقية أو درامية متبقية.
    -   **التقرير النهائي (Final Report):** يتم تجميع كل المخرجات في كائن JSON شامل وإرساله إلى الواجهة.

التقنيات المستخدمة
- **Node.js و Express.js**: لبناء الخادم وتقديم API.
- **Axios**: للتواصل مع واجهة Gemini API.
- **uuid**: لإنشاء معرفات فريدة للجلسات.
- **HTML/CSS/JS (Tailwind)**: لبناء واجهة المستخدم.

كيفية التشغيل
1.  `npm install`
2.  `npm start`
3.  افتح المتصفح على `http://localhost:3000`

خاتمة
هذا المشروع يمثل منصة متكاملة لتطوير الأفكار القصصية بشكل احترافي، ويعتمد على التعاون بين وكلاء متخصصين لضمان جودة الفكرة من جميع الجوانب السردية والفنية.
